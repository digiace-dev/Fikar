# Project Workflow Rules

## 1. Folder Structure & Organization

```
project/
├── src/
│   ├── main.cpp           # Main program (deployment)
│   └── config.h           # Configuration & constants
├── test/
│   ├── test-<feature>.cpp # Partial/unit tests
│   └── [test-*.cpp]       # One test per feature
├── platformio.ini         # Build & environment config
├── .env                   # Environment variables
└── _docs/
    ├── _core/
    │   └── rule.md        # This file - workflow rules
    └── [documentation]
```

**Purpose:**
- `_docs/` → Information & documentation only
- `test/` → Partial programs (feature tests, not full integration)

## 2. Test Strategy - Test per Feature

Each feature/module gets its own test file in `test/` folder.

**Test File Naming:** `test-<feature>.cpp`

### Test File Convention:

| Purpose | File | Config Entry | Trigger |
| --- | --- | --- | --- |
| Feature A test | `test-featureA.cpp` | `[env:test-featureA]` | `platformio test -e test-featureA` |
| Feature B test | `test-featureB.cpp` | `[env:test-featureB]` | `platformio test -e test-featureB` |
| Integration test | `test-integration.cpp` | `[env:test-integration]` | `platformio test -e test-integration` |

## 3. PlatformIO Environment Convention

### Environment Naming Pattern:

```ini
[env:test-<feature>]
platform = <platform>
board = <board>
framework = <framework>
test_dir = test
```

### Production Environment:

```ini
[env:production]
platform = <platform>
board = <board>
framework = <framework>
```

### Command Examples:

```bash
# Run single test
platformio test -e test-feature1

# Run all test-* environments
platformio test

# Build production
platformio run -e production
```

## 4. Configuration Management - `src/config.h`

Centralize all configuration in one header file:

- Hardware pin definitions
- Calibration values
- Threshold parameters
- Timing constants
- Serial baud rates

### Example Structure:

```c
#ifndef CONFIG_H
#define CONFIG_H

// Hardware
#define PIN_SENSOR_1 34
#define PIN_RELAY 26

// Parameters
#define THRESHOLD_LOWER 60
#define TIMEOUT_MS 5000

#endif
```

**Rule:** No hardcoded values in source code. Always reference `config.h`.

## 5. Test File Structure

### Simple Arduino Format:

```cpp
#include <Arduino.h>
#include "../src/config.h"

void setup() {
  Serial.begin(BAUD_RATE);
  // Initialize test hardware
}

void loop() {
  // Test logic
  // Output to Serial for debugging
  delay(interval);
}
```

### Key Requirements:

- Include `config.h` for pin/parameter consistency
- Setup pins from `config.h` definitions
- Output debug info to Serial
- Simple delay-based loop structure
- Clear comments explaining test flow

## 6. Development Workflow

### Step 1: Create Test File
```
test/test-<feature>.cpp
```
Implement feature test logic.

### Step 2: Add Environment
```ini
[env:test-<feature>]
platform = <...>
board = <...>
framework = <...>
test_dir = test
```

### Step 3: Update config.h
Add any new `#define` constants needed.

### Step 4: Test & Debug
```bash
platformio test -e test-<feature>
```
Monitor Serial output for results.

### Step 5: Integrate
Move validated logic into `src/main.cpp`.

## 7. Naming Convention

| Element | Pattern | Example |
| --- | --- | --- |
| Test files | `test-<feature>.cpp` | `test-sensor.cpp` |
| Environments | `[env:test-<feature>]` | `[env:test-sensor]` |
| #define constants | `FEATURE_PARAM` | `SENSOR_PIN` |
| Functions | `setup()`, `loop()` | Arduino standard |
| Variables | `snake_case` | `raw_value` |

### Test File Header:

```

### config.h Comments:

```

### Environment Table:
Document all test environments in section 2 above.

## 9. .env File Management

The `.env` file stores environment-specific paths:

```
PLATFORMIO_BUILD_DIR=.pio/build
PLATFORMIO_LIBDEPS_DIR=.pio/libdeps
PLATFORMIO_PACKAGES_DIR=.pio/packages
PLATFORMIO_TEST_DIR=test
```

**Note:** Auto-generated by build tools. Minimal manual edits.

## 10. Pre-Deployment Checklist

- [ ] All test files in `test/` have corresponding `[env:test-*]` in `platformio.ini`
- [ ] All constants defined in `src/config.h` (no hardcoded values)
- [ ] Test files output debug info via Serial
- [ ] Build runs without errors: `platformio run -e production`
- [ ] All tests pass: `platformio test`
- [ ] config.h includes unit/description in comments
- [ ] No production code references test files

## 11. File Organization Quick Reference

```
_docs/
  └─ Information & documentation only
      (PRD, guides, specs, meeting notes)

test/
  └─ Partial test programs per feature
      (Each file tests one aspect)

src/
  ├─ main.cpp  → Full integrated program
  └─ config.h  → All configuration centralized
```
